# Fix-All (2026-11-12) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Ship every fix the 2026-11-12 error analysis found, and measure each on AndroidWorld to reach the best SR with one model.

**Architecture:** There are three kinds of fix:
- harness fixes, already in V11;
- inference policy (masking);
- one data fix: recovery rows with explicit on/off state.

Each fix is measured separately. Runs use 6 emulators in parallel, and the final number comes from the full 116 tasks.

**Tech Stack:** `benchmarks/aw` harness (pytest), `benchmarks/train` (`build_recovery_data.py`, `train_d1.py`), emulator host chains (`stage2_chain_v4{,p}.sh`, `split_tail.py`).

**Spec:** `benchmarks/results/2026-11-12-erroranalysis/FIXES.md`, `benchmarks/results/2026-11-12-recovery/README.md`

## Global Constraints

- One model, no planner, no external model. Training data is AndroidControl plus augmentation; no self-play (the emulator is used for evaluation only).
- Never touch client processes or GPU memory on any host. Cap our own GPU use.
- Every number carries n/N. Every change gets its own paired run against its parent run.
- Full training happens only after the inference/pilot gates in the recovery README pass.

## Review Focus

1. Masking can turn loops into early stops (49 → 56 on v3). Compare the count of premature stops against the parent run.
2. Recovery rows can teach backing out of on-path screens. Measure P(back) where gold ≠ back on validation.
3. Rebalanced chains must not run a task twice. Merge the run dirs by task and check for duplicates.
4. Explicit "on/off" text changes the state the model reads. Render it identically in training and serving (`ac_common`).
5. The Chrome first-run fix must run before episodes start, never during one.

### Task 4: Recovery pilot (gate before any training)

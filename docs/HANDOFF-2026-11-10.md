## 1. One paragraph

The checkpoint `episodic-s0` was trained with three signals that the benchmark path never sent it —
an a11y element list (50% of training steps), an app-memory line (100% of rows), and a history
format it actually saw — while the harness sent two signals it had never seen (coordinates and
`-> ok` in history, and duplicated `Step N:` prefixes). Ten separate infrastructure defects in the
chunked benchmark runner were found and fixed in the process. After enabling `track: VA` and
correcting the history format, `ExpenseAddMultiple` went from **60 steps with 56 clicks that never
touched SAVE** to **9 steps ending in a click at (454, 1302) — the exact centre of SAVE** — but the
task still scores 0, because it declares done while the expense is not saved. Grounding was never
the binding problem; **termination** is.

## 3. The ten defects found on 2026-11-10

All were mine, none were the model's. Grouped by where they live.

### 3.1 Contract (train ≠ serve)

| # | defect | evidence | state |
|---|---|---|---|
| C1 | `build_state` added `Step {i}: ` to history entries that already began with `Step N:` | episodic corpus: **159,954/159,954** entries prefixed → rendered `Step 1: Step 1: click`. `cur15k` corpus: **0/57,096** | fixed both sides + repair path |
| C2 | harness history was `click (647,886) -> ok` | training history: coordinates in **0 of 99,536** click lines, `->` in **0 of 159,954** lines | fixed |
| C3 | `d1_api` passed `app_intent=…` unconditionally while `ALLOW_APP_INTENT=False` | trainer never emits that line | fixed, gated |
| C4 | **`track: V`** ⇒ element list never sent | `--track mix` ⇒ 50% of steps; **99.2%** of training rows carry `cands`, median **34** | fixed → `track: VA` |
| C5 | harness sent `bbox` as a LIST + only `clickable`; server read `bbox_pixels` as a DICT + `is_visible`/`is_editable`/… | 65 elements in → **0 survivors** out | fixed in `_element_dicts` and `_normalise` |
| C6 | `if cands is not None` is true for `[]` ⇒ `ans["target_el"]` on a V request | `KeyError: target_el` → **HTTP 500** | fixed to `if cands:` |
| C7 | **`apps` line never sent** | 100% of rows have it | **OPEN** — see §5 |

### 3.2 Infrastructure (the benchmark runner)

| # | defect | symptom |
|---|---|---|
| I1 | `suite.tasks: all` needed an importable registry | `ImportError: suite_assets` — two copies of `android_world`, the installed one is not `/app`'s. Fixed: enumerate from the budget table |
| I2 | container had no `/out` bind mount | results written to container `/tmp`, destroyed on restart (which happens every ~20 min) |
| I3 | a fresh container has no `pyyaml` | `ModuleNotFoundError` **after** a 6-min restart |
| I4 | stale harness silently reused — `tar` piped to `/dev/null` | ran yesterday's `run_bench.py` while printing `harness_ok` |
| I5 | `--run-root` + `--run-id` nested the run dir | `<root>/<id>/<id>`; recorder opened a fresh `index.db`, re-ran completed work |
| I6 | `index.db` owned by host user, container runs root | `sqlite3.OperationalError: attempt to write a readonly database`, **at commit, after a whole episode** |
| I7 | `rebuild_index` could not delete rows | index said 14 ok, disk had 13 → preflight blocked forever |
| I8 | `CONTAINER_OUT=/out/$RUNID` while `/out` **is** the run root | second nested run; `skipped: 5`, 0 new episodes, summary looked normal |
| I9 | passing `--run-id` at all joins the id again | same class as I8; fixed by not passing it |
| I10 | preflight piped through `tail` | pipeline status was `tail`'s (0), so a FAILED gate still let the chunk run — it had found a real defect |

**New guard:** the chunk script now aborts (exit 3/4) if a round produces no episodes on the host,
or if episodes appear in a nested `/out/*/episodes`. This is the check that would have caught
I5/I8/I9 in one minute instead of five restarts.

## 5. What is still broken, in priority order

### P1 — `apps` line is still never sent (100% of rows)
`train_d1.py:465` builds `AppMemory` (2,253 items) and `:129` passes `memory.query(goal)`; `d1_api`
passes `apps=None`. Two options:
- **A** ship the TF-IDF state with the checkpoint (~small) and query at serve time. A query that
  finds nothing returns `[]` and the line disappears — still unlike training, but at least the
  mechanism exists.
- **B** retrain with `--no-memory` for a clean contract. ~1.5 h GPU.
Not started.

### P2 — termination, not grounding, is the binding failure
Every failed task that reaches the right screen then declares done (`ExpenseAddMultiple`: 9 steps,
correct SAVE click, `declared_done=True`, `success=False`) or exhausts the budget. The `is_done`
readout is unusable: on 824 validation rows `step == n_steps` and `action == status` are **the same
137 rows** (137/137; **0 positives** among 687 non-status rows), so `auroc_nonterm` is `null` and
`is_done` is a restatement of the action label. `risk @ 50% coverage = 0.670`. The gate is OFF by
default (`done_threshold: 0.0`) and must stay off.
**A task-completion signal does not exist in this corpus.** It needs a corpus with mid-episode
completion states, or the live environment.

### P3 — `type_text` cannot invent text
It is a pointer read over the state (`ac_common.py:19-20`), so a field whose value is not present in
the goal returns `''` → `text_missing` → the step is wasted. Observed on
`ContactsNewContactDraft` (3 of 12 steps) and `BrowserMultiply` (`typed=''` twice).

### P4 — `eval_d1.py` silently drops history
`eval_d1.py:74` reads `r.get("previous_actions")`; the corpora carry `history`. Measured:
`compact_validation` **690/827 (83.4%)** rows have non-empty `history`; `compact_cur15k`
**12,365/15,000 (82.4%)**. Therefore **both 64.07% (E2) and 55.78% (episodic-s0) were measured with
history dropped** — they are lower bounds, not capabilities. Not fixed; do not quote either as a
capability number until re-run.

### P5 — `GOLD_KEEP` leaks into training candidate selection
`ac_common.GOLD_KEEP["idx"]` forces the gold candidate to survive the `D1_MAX_CANDS` cap at train
time. It is absent at eval and serve, so the same screen can produce a different candidate set in the
three paths. Unmeasured; likely small at cap 0 (no cap) but it must be measured before any VA number
is trusted.

### P6 — `_slug` truncates episode ids at 24 chars
`runner.py:33`. Two long task names can collide, and any hand-written `rm`/`grep` on episode ids will
miss (this cost a real chunk: `ExpenseAddMultipleFromMarkor` stores as `…fromma_`).

## 9. The honest summary

- The action layer is verified: **Gate A 41/41** on the live device, every action's *consequence*
  asserted, `type_text` proven to replace rather than append.
- Grounding was fixed by sending what the model was trained on: `(454,1302)` is the SAVE centre,
  versus a 537 px miss before.
- **No task success was gained.** 0/5 on the re-run, 4/19 overall.
- The reason is not perception, it is **knowing when to stop** — and the corpus cannot teach that,
  because in AndroidControl "done" and "the action is `status`" are the same 137 rows.
- Two numbers in circulation (**64.07%** and **55.78%**) were both measured with history dropped
  (P4). They are lower bounds. Do not quote them as capability.
- The next real decision is P1 (ship the memory / retrain without it) and P2 (a completion signal
  that is not a restatement of the action label). Neither is a harness problem.

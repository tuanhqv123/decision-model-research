1. The problem, in plain words

A "phone agent" looks at the screen and decides the next step: where to tap, whether to scroll, what to type.

The usual way today: a large language model writes the action as text, often after a passage of reasoning, and software parses that text. This costs three things:

  • Slow: it writes one token at a time, and longer reasoning takes longer.
  • Fragile: a badly formatted answer cannot be parsed.
  • No sense of doubt: no number says whether to act, ask, or stop.

Like a waiter who takes an order by writing a paragraph by hand, when ticking boxes on a printed form, plus "90% sure", would do.

2. Why a decision model, and why d1-2B

A decision model writes no text. It reads the screen once and answers questions with fixed options: which action? which element? which direction? which app? Every answer comes with a probability.

Why Liquid AI's d1-2B:

  • The right kind: one pass, no tokens, probabilities built in.
  • Small: 1.92 billion parameters; about 0.12 s per decision on one RTX 4090 (0.25 s when the GPU is shared with a busy job).
  • Open: the weights can be fine-tuned.
  • Reads the image and the on-screen element list, so it picks a button instead of guessing coordinates.

Research question

Can a model that writes nothing and only "ticks options" pick phone actions as well as text-writing models many times its size?

And are its probabilities usable for deciding when to act alone and when to ask a person?

3. The test: AndroidControl

Google recorded real people using Android apps. The test set has 1,543 episodes and 8,444 steps. At each step the model sees the screen and what the person did before, and must predict the person's next action.

AC-Low: with a step instruction

"Click the square next to the Flowers folder." Tests following an instruction.

AC-High: goal only

"Rename the Flowers folder to Flora." Tests working out the next step. Much harder.

A step counts as right only if the action type and every detail are right: the element, the direction, the text.

What we did

  • Used all of AndroidControl's training split: 13,594 episodes, 88,308 steps, with every test episode removed.
  • Showed each step in several forms: sometimes the goal only, sometimes with 1–4 step instructions.
  • Trained one pass over the data (about 16 hours on one RTX 4090).

Like a trainee who watches an expert use a phone 88,000 times, sometimes with the expert's instructions read aloud and sometimes without.

5. Compared with other models (AC-High, % of steps right)

Reading the chart: DMA-2B is the best 2B model reported, and above several 7–9B models that write text. Four 3–7B models and the very large ones are still higher.

6. Are the probabilities usable?

The idea: let the model act alone only when it is sure enough, and ask a person otherwise.

Choose the threshold on half of the episodes, test it on the other half, and repeat 200 times:

  • For at most 20% wrong: the model acts alone on 80% of steps, 19% wrong.
  • For at most 15% wrong: it acts alone on 50%, 13.7% wrong.
  • The untrained base model: almost no threshold reaches the 20% level.

To be honest

The model is somewhat over-confident: on average it says "88.7% sure" but is right 74.2% of the time. Use the probability to rank how sure it is and pick the threshold on real data; do not read it as an exact probability.

Like a driver who knows which roads they tend to get lost on and asks there, while being a little over-confident overall.

8. What we learned

1. The right data, and enough of it, beats every trick

The largest jump came from using all of the data, not from a technique.

2. Score with one rule

The same model moves 3.7 points when "may it say done?" changes. State the scoring rule.

3. Knowing when to stop is the hardest part

The main error is not a wrong tap, but deciding the task is done while the screen is still loading.

4. Right steps are not a finished task

74% of steps right, but only 30.6% of episodes with every step right; longer episodes are harder.

10. Limits, stated plainly

  • One seed. A gap of a few points to another model is not enough to rank them.
  • Other models' numbers come from their papers: different prompts, action sets and scoring, so the comparison is approximate.
  • Two scoring rules: DMA-2B is scored in AC's own action set (no "done"); the base model is scored with "done".
  • Imitation with the correct history: the model never saw its own mistakes, and AC does not measure whole-task success.
  • Needs the screen's element list; it cannot run from the image alone.
  • Types only text that appears in the goal or the instruction.
  • Over-confident: 88.7% sure on average, 74.2% right.

In one sentence

A 2B model that writes no text and only ticks options in one look gets 90.5% / 74.2% of AndroidControl steps right, level with text-writing models many times larger, and knows when it is unsure well enough to act alone on 80% of steps with 19% of them wrong.

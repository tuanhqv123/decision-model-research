## Objective (what "public value" means here)
Produce a **defensible, reproducible result** for the paper — not a claim we cannot defend.
Minimum acceptable outcome:
1. The **online AndroidWorld loop actually runs** (emulator + d1 decisions + AndroidWorld's own scorer).
2. A **measured success rate on a disclosed task subset**, reported **with baselines side by side**
   (random agent and/or human reference) and with the exact protocol (tasks, steps, seed, n_combinations).
3. **Calibration evidence on the online loop** (confidence vs outcome; coverage/risk at a gate threshold),
   which is the paper's actual differentiator.
4. An honest writeup section that states what is and is not established.

**Explicitly NOT the goal:** claiming a SOTA beat. Feynman's audit found **no peer-reviewed AndroidWorld
baseline** (all arXiv preprints / self-reports) and the often-quoted `GUI-Owl-1.5-2B = 67.9%` has **no
primary source**. Do not cite either as fact.

## Priority override (added after the Feynman gap analysis)
The paper spine is **N1**: CE vs proper-scoring vs joint-calibration on identical data, measured as a
*confidence→correctness* (AUROC / selective-risk) signal, with ≥3 seeds and CIs. That is what makes the
paper defensible; the emulator is *infrastructure* for N3.

## Known blockers / facts (from Feynman briefing, `outputs/androidworld-online-loop-briefing.md`)
- HTTP `/screenshot` returns **pixels only** — no a11y tree. Track `V` only (E2 checkpoint is V-only anyway).
- Server default is `n_task_combinations=2, seed=42`; `run.py` default is `1, seed=30`. Match and disclose.
- Success = device-state `is_successful`; a stalling agent scores 0.
- `adb root` needs the `google_apis` (userdebug) image — that is what the Dockerfile builds.
- Build is slow because `opencv-python` compiles from source (~20+ min single-threaded).

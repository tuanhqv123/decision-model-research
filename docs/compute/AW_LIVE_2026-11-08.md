## Two bugs the live run found (both now fixed with regression tests)

**1. `GET /screenshot` requires `wait_to_stabilize`.** A bare request returns **422 Unprocessable Entity**. The
liveness `noop` layer forgot the parameter, so it reported a dead device while the device was healthy — the exact
false-crash class that produced the "25% crash rate" earlier in the project. Fixed in
`awenv/liveness.py` plus a source-level regression test (`test_noop_probe_sends_the_required_screenshot_parameter`).
`aw_smoke.py` already had it right, which is how the discrepancy was spotted.

**2. The upstream Dockerfile still needs patch #3.** `PIL` is imported by
`android_world/task_evals/utils/user_data_generation.py` but Pillow is undeclared; the container starts and then
dies on import. Fixed by `RUN uv pip install --system pillow` after the project install. The runbook predicted this
and it was still missed on the first attempt — the build takes ~40 min because `eclipse-temurin:17-jdk-jammy` has no
Python and the stage compiles it. **Use the layer cache; do not "clean" it.**

## Reachability note for the harness

The host's `adb` cannot see the emulator inside the container (separate network namespace), so `Gate A` must run
**inside** the container:

```bash
docker exec -e AW_GATE=1 -e AW_URL=http://127.0.0.1:5000 \
  -e AW_ADB=/opt/android/platform-tools/adb -e PYTHONPATH=/tmp/awh \
  aw-emu python3 -m pytest /tmp/awh/tests/test_device_gate_a.py -q
```

That is a change from the 2026-11-06 procedure, where the harness ran on the host against a host-side emulator.

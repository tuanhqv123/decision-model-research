# PRE-REGISTRATION — v2a online (2026-11-11), written before any v2a online result

## Arm
v2a seed 0: d1-2B, contract v2a — the element is chosen from the AndroidWorld element list (`cap40_reading`, ≤ 40),
the app is chosen from AndroidWorld's 33 launchable apps, and at the first step of a task (empty history) the server
allows only `open_app` or `status`. Training: `cur15k_v2` (14,965 AndroidControl rows with AW-style element lists) +
`compact_awgen_v2a` (1,736 goal→app rows from AndroidWorld's own parameter generator on a captured home screen, no task
run; the 116 test instances are refused; 19 of 80 single-app templates held out). R1's recipe otherwise (1 epoch, lr
1e-5, warmup 30, frozen embedding, batch 16), image width 720.

**Disclosed:** the goal→app rows come from the 116 task templates (practice parameters); for parameter-free
templates (e.g. "Turn wifi on.") the practice goal text equals the test goal text.

## Comparison and protocol
Same 116 instances (`task_random_seed` 30), same emulator host, harness v4, `sweep_infra.py` + watchdog; frozen
`benchmarks/aw/paired_sr.py` against R1 s1 (the stronger R1 seed) and B0′, on 116 (primary) and 104 (sensitivity);
IR (answer-only) tasks reported separately (v2a has no `answer`: expected 0/25).

## Decision rule (one seed)
* No claim from one seed. Seeds 1–2 are trained and run iff v2a s0 vs R1 s1 gives w − l ≥ +6 on the 116 (the A1 bar).
* If w − l ≤ 0: stop and diagnose before any further training.

## Predictions (mechanism, written now)
1. Unresolvable `open_app` names: 29–36% (R1) → **0** (by construction).
2. Task-completion episodes in which no app was ever opened: 24–25 (R1) → **≤ 8** (the floor "Verify" tasks may still
   end with `status` at step 0).
3. Clicks on non-interactive elements: 21–29% no-effect + 8–9% effect (R1) → **lower**; elements are chosen from the
   list, which still contains labelled non-interactive elements, so not 0.
4. Held-out templates (19, never seen in the generator rows): first-step app accuracy on `compact_awgen_heldout`
   reported offline next to the seen templates; a gap > 20 points means the app choice memorised templates.
5. Premature `status` is not addressed by v2a: no prediction of improvement.

## Kill rules (offline, before the online run)
* `validation_v2` step accuracy < R1's 61.9% − 3 points → do not run online; diagnose.
* `awgen_heldout` app accuracy < 50% → the app choice did not generalise; run online anyway (it is the measurement)
  but report it as the cause if the start problem persists.

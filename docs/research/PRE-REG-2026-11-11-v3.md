# PRE-REGISTRATION — v3 (2026-11-11), written while v3 seed 0 trains, before any v3 result (offline or online)

## Arm
v3 seed 0: d1-2B (`LiquidAI/d1-2B@cfe5760`), contract v3 = v2a (element chosen from the AndroidWorld element list, app chosen
from AndroidWorld's 33 launchable apps, first step restricted to `open_app`/`status` at the server) **plus**: the state says
`Progress` (step n, n−1 actions done), `Current app` (AndroidWorld apps by their app-list name), and every previous action
with the element it acted on and whether the screen changed (last 12); keyboard keys are excluded from the element list;
option texts v3 (scroll texts say what AndroidWorld does, element options carry the state `[id]`, action options use the
history verbs, `status` = "the goal is fully achieved on this screen").

Training: every step of 4,197 AndroidWorld-like AndroidControl goals (`compact_awlike_full_v3`, 27,454 rows) + 1,736
goal→app rows from AndroidWorld's generator (19 templates held out). 1,824 steps × 16, lr 1e-5, warmup 30, frozen embedding,
image width 720. Run card: `docs/research/RUNCARD-v3_s0.md`. Trained on the 5090 host (torch 2.7.1+cu128).

**Format verified before results:** parity of the training forward against d1 serving (`system_one_batch`) on 6 real v3 rows,
all 11 supervised choice questions equal to 3 decimals (PARITY_V3 PASS, 2026-11-11); every gold answer of every train/val row
is one of its question's options (dry run over 30,480 rows).

**Disclosed:** as for v2a, the goal→app rows come from the 116 task templates with practice parameters.

## Checkpoint selection (offline, fixed now)
Checkpoints at steps 450, 900, 1350, 1800 and 1824 are evaluated on `validation_v3` (827 AndroidControl validation steps) and
`awgen_heldout_v3` (463). The online checkpoint is the one with the highest `validation_v3` step accuracy; a tie goes to the
later step. `awgen_heldout_v3` is reported, not used for selection.

## Comparison and protocol (online)
Same 116 instances (`task_random_seed` 30), same emulator host, harness v5 (`awhV5.tgz`, md5 b931019a…; refuses to start
unless `/health` reports contract v3 and image width 720), `sweep_infra.py` + watchdog; frozen `benchmarks/aw/paired_sr.py`
against **R1 s1** (14.8%, 17/115, the stronger R1 seed) and B0′, on 116 (primary) and 104 (sensitivity); the 25 answer-only
tasks reported separately (v3 has no `answer`: expected 0/25).

## Decision rule (one seed)
* No claim from one seed. Seeds 1–2 are trained and run iff v3 s0 vs R1 s1 gives w − l ≥ +6 on the 116 (the A1 bar).
* If w − l ≤ 0: stop and diagnose before any further training.

## Predictions (mechanism, written now)
1. Unresolvable `open_app` names: 29–36% (R1) → **0** (by construction, as v2a).
2. Premature `status` (declared on a row whose gold is not `status`): on `validation_v3`, fewer than R1's **56–59 per seed**
   (171 over 3 seeds, 103 of them one step before the end; `2026-11-11-DIAGNOSIS-why-low.md`). Online: fewer episodes ended by `status` before the task's success than R1 s1.
3. Repeating an action on a screen it did not change (first encounter): R1 41.2% → **lower**, because the history now says
   `→ no change`.
4. Held-out templates: first-step app accuracy on `awgen_heldout_v3` within 20 points of the seen templates; a larger gap means
   the app choice memorised templates.
5. Information-retrieval tasks: 0/25 (no `answer` action).

## Kill rules (offline, before the online run)
* `validation_v3` step accuracy of the selected checkpoint < R1's 61.9% − 3 points → do not run online; diagnose.
* `awgen_heldout_v3` app accuracy < 50% → run online anyway (it is the measurement), report it as the cause if the start
  problem persists.

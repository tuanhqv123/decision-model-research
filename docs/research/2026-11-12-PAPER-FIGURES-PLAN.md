# Paper figures and tables: what each shows, where its numbers come from (2026-11-12)

The format follows the published mobile-agent papers we compare against:
- **MobileRL** (arXiv 2509.18119): Fig. 4 pass@k by complexity level; Fig. 5 step win rate by category; Table 2 AndroidControl Type / Grounding / SR.
- **AndroidGen** (arXiv 2504.19298): Table 9 easy / medium / hard.
- **AndroidWorld** (Rawles et al. 2024): difficulty labels and optimal steps from upstream `task_metadata.json`.

Every number is generated by a script from files in the repo. None is typed by hand.

The comparison rule is AGENTS.md M4: no number is compared with a number from another harness unless the difference is stated next to it. Rules for this paper:
- AndroidGen's AndroidWorld counts fit 111 tasks; ours are 116.
- MobileRL's complexity levels have n = 49/41/11/15; ours, ceil(complexity) over the class complexities, are 45/41/9/21.
- MobileRL reports pass@k over 8 sampled attempts. We report one deterministic attempt (argmax) per task.

## Logged during every run (already in the traces, checked 2026-11-12)

- **Step rows:** `state_in` (goal, history, full element list), `action_raw` (action, element, confidence, app, text), `model_ms`, `env_ms`, `screen_changed`, `ui_changed`, `fresh_wait_polls`, screenshot path.
- **Episode result rows:** `score`, `task_successful` (the goal held even without a declaration), `declared_done`, `n_steps`, `setup_error`, `unscored`.
- **Episode header:** protocol and agent policy (harness version, masking, fresh_wait, answer_format), so every number carries its setup.

## Not available, and why

**pass@k** needs repeated attempts per task. Our model is deterministic (argmax), so k identical attempts carry no information.
- The honest variance measure is 3 runs on the same instances, which only measures environment nondeterminism.
- Sampling from the model's distribution would be a different policy and must be named as one.

We report pass@1 only, and say so.
